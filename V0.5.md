# v0.5 — Human-in-the-Loop durável

A v0.5 transforma o branch de handoff da v0.4 em uma interrupção real do LangGraph.

## Fluxo

```text
classify
   |
   +-- pricing/scheduling --> tool_agent --> END
   +-- normal -------------> respond -----> END
   +-- needs_human --------> handoff
                                |
                                +-- interrupt(payload)
                                      |
                                 CHECKPOINT POSTGRES
                                      |
                                 espera humano
                                      |
                              Command(resume=...)
                                      |
                         +------------+------------+
                         |                         |
                      approve                    reject
                         |                         |
                      handoff               handoff_rejected
                         |                         |
                        END                       END
```

## Regras de segurança/execução

- `thread_id` continua namespaced por tenant.
- Enquanto houver interrupt pendente, `POST /messages` retorna HTTP 409.
- Resume só é aceito para ADMIN, MANAGER ou AGENT.
- v0.5 permite exatamente um interrupt pendente por thread.
- O `handoff_node` não executa side effects antes de `interrupt()`.
- O interrupt e o estado ficam no PostgreSQL checkpointer e sobrevivem ao restart da API.

## Endpoints

- `POST /api/v1/agent/threads/{thread_id}/messages`
- `POST /api/v1/agent/threads/{thread_id}/resume`
- `GET /api/v1/agent/threads/{thread_id}/state`
- `GET /api/v1/agent/threads/{thread_id}/history`

Resume:

```json
{
  "decision": "approve",
  "note": "Aprovado pelo operador."
}
```

## Decisão importante

Código executado antes de `interrupt()` deve ser side-effect free ou idempotente, porque o LangGraph reinicia o node interrompido desde o início quando a execução é retomada.
