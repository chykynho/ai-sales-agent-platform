# v0.7 — Configurable Multi-Tenant SaaS Runtime

## Goal
One deploy, one API, one PostgreSQL/Redis stack, many clients. Tenant behavior is data-driven instead of code forks.

## Tenant-scoped configuration
Each tenant owns:
- company/brand name and assistant name
- locale, timezone and response tone
- custom instructions
- enabled tool allowlist
- business hours
- RAG top-k and minimum similarity
- configuration version
- product catalog and prices

## Control plane
`scripts/provision_tenant.py` is an idempotent operator-side control-plane primitive. It creates/updates a tenant, admin user, runtime config and default product catalog without exposing a cross-tenant public API.

## Runtime policy
The model receives only tools enabled for the authenticated tenant. Backend execution also uses the filtered registry, so the allowlist is enforced server-side rather than being prompt-only.

## Dynamic catalog
`check_price` now queries `tenant_products` using authenticated `tenant_id`. The same code `PRO` can have different prices for different tenants.

## No deploy required
`PATCH /api/v1/tenant/config` and `PUT /api/v1/tenant/products/{code}` change behavior on the next request. No image rebuild or process restart is required.
