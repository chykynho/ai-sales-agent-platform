# v0.14 — CI/CD, Quality Gates e Supply Chain Security

A v0.14 fecha a lacuna entre uma plataforma funcional e uma entrega governada. Ela adiciona integração contínua, delivery por tag, análise estática, auditoria de dependências, secret scanning, image scanning, SBOM, hardening do Docker e governança básica do repositório.

## CI

Workflow: `.github/workflows/ci.yml`.

Gates obrigatórios:

1. **Quality Gate** — Python 3.12, Ruff, Bandit, pytest + coverage e `pip-audit`;
2. **Secret Scan** — Gitleaks com histórico completo;
3. **Container Security Gate** — build `production`, usuário não-root e Trivy;
4. **Docker Integration Gate** — PostgreSQL + Redis + API, readiness, regressão e smoke de resiliência.

## CD

Workflow: `.github/workflows/release.yml`.

Tags `v*` geram uma imagem `production`, passam por Trivy e são publicadas em:

```text
ghcr.io/chykynho/ai-sales-agent-platform:<tag>
ghcr.io/chykynho/ai-sales-agent-platform:latest
```

O build de release habilita provenance e SBOM do BuildKit.

## Docker hardening

A v0.14 adiciona `.dockerignore`, evitando que `.env`, `.git`, caches, relatórios e ZIPs entrem no contexto do build.

O Dockerfile passa a ter dois targets:

```text
development -> testes/quality/security tools
production  -> runtime sem dev/security tools + USER app
```

O Compose local usa `development`. O CI/CD escaneia e publica `production`.

## Coverage gate

O baseline inicial é 25%. Ele é deliberadamente conservador para não transformar a v0.14 numa reescrita de testes. A política recomendada é **ratchet**: nunca reduzir o threshold e aumentá-lo conforme novas suítes forem adicionadas.

## Governança

- `.github/dependabot.yml` para pip, Docker e GitHub Actions;
- `.github/CODEOWNERS` com `@chykynho`;
- `SECURITY.md`;
- branch protection/ruleset recomendado para `main`.
