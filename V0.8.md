# v0.8 - WhatsApp Business / Meta Cloud API channel adapter

## Goal
Connect a public WhatsApp webhook to the existing multi-tenant LangGraph agent without creating one application per customer.

## Architecture
`Meta webhook -> signature verification -> tenant resolution by phone_number_id -> idempotent channel_event -> fast 200 ACK -> background processing -> Customer/Conversation/Message -> LangGraph -> outbound provider -> channel_event audit`.

## Security
- GET verification uses `WHATSAPP_VERIFY_TOKEN`.
- POST delivery requires `X-Hub-Signature-256` validated with HMAC-SHA256 and `WHATSAPP_APP_SECRET`.
- Access tokens are not stored in PostgreSQL. A tenant channel account stores only an `access_token_env` variable name.
- The smoke test uses `outbound_mode=mock`, so no Meta access token is required.

## Multi-tenant resolution
Inbound webhooks do not contain our JWT. The tenant is resolved by the WhatsApp `phone_number_id`, which is unique in `channel_accounts`.

## Idempotency
`provider + provider_event_id` is unique in `channel_events`. A replay of the same WhatsApp message is acknowledged but not processed a second time.

## Production note
The in-process background task is sufficient for the v0.8 lab. A production deployment should move accepted events to a durable queue/worker so API restarts cannot lose accepted-but-not-yet-processed jobs.
