# v0.12 — Observabilidade / SRE

A v0.12 adiciona observabilidade operacional à AI Sales Agent Platform sem alterar o schema do banco e sem remover funcionalidades validadas na v0.11.1.

## Objetivo

Transformar a plataforma de um sistema funcional de agentes de IA em um serviço que possa ser operado, diagnosticado e apresentado com práticas de SRE/AIOps.

## Pilares

### 1. Logs estruturados JSON

Cada requisição HTTP gera log estruturado com, quando disponível:

- `request_id`
- `tenant_id`
- `conversation_id`
- `call_sid`
- `trace_id`
- `span_id`
- método, rota, status HTTP e duração
- service, version e environment

Segredos conhecidos são redigidos antes de irem para logs estruturados.

### 2. Métricas Prometheus

Endpoint: `GET /metrics`.

Famílias principais:

- HTTP: tráfego, 5xx, latência e requisições em voo;
- tenant: requisições e custo LLM acumulado;
- LLM/AgentRun: requests, duração, tokens, custo e status;
- tools: chamadas, erros e duração;
- RAG: buscas, duração e quantidade de chunks;
- Voice: sessões, STT, Realtime e sessões ativas;
- Twilio: call status, stream status e erros;
- runtime Python/processo: CPU, memória e GC via cliente Prometheus.

`request_id`, `conversation_id`, `call_sid` e `trace_id` não são labels Prometheus para evitar cardinalidade descontrolada. Esses identificadores ficam em logs e traces. `tenant_id` é usado apenas nas métricas explicitamente por tenant e pode ser desativado por configuração.

### 3. OpenTelemetry tracing

Tracing manual da fronteira HTTP e spans adicionais em:

- SQLAlchemy/PostgreSQL;
- Redis;
- HTTPX/requests externas;
- tools;
- RAG;
- STT;
- OpenAI Realtime;
- turno de Voice/Twilio.

O exporter OTLP/HTTP é opcional. Sem `OBSERVABILITY_OTLP_ENDPOINT`, a API funciona normalmente e continua gerando `trace_id` local para correlação.

### 4. Health operacional

- `/api/v1/health/live`: processo vivo;
- `/api/v1/health/ready`: PostgreSQL + Redis disponíveis;
- `/api/v1/health`: compatibilidade, retorna o readiness.

### 5. Golden Signals

A v0.12 expõe dados para:

- **Latency**: histograms HTTP, LLM, tools, RAG, STT e Realtime;
- **Traffic**: requests HTTP, LLM, tools, RAG, Voice e Twilio;
- **Errors**: HTTP 5xx, LLM failures, tool failures e erros Twilio;
- **Saturation**: requests in-flight, active voice sessions, CPU/memória/processo.

## Stack opcional local

Arquivo `docker-compose.observability.yml` adiciona:

- Prometheus 3.14.0 — `http://localhost:9090`
- Grafana 13.2.1 — `http://localhost:3000`
- Tempo 2.10.7 — `http://localhost:3200`

O stack é opcional: o primeiro upgrade valida a API e `/metrics` sem obrigar Grafana/Prometheus/Tempo a ficarem ativos.

## Alertas iniciais

- taxa HTTP 5xx > 5%;
- latência HTTP p95 > 2 s;
- taxa de falha LLM > 10%;
- taxa de falha de tools > 10%.

São thresholds iniciais de laboratório, não SLOs finais de produção.

## Dashboard

O Grafana provisiona automaticamente `AI Sales Agent Platform - SRE / Golden Signals`, com painéis para tráfego, disponibilidade, p95 HTTP/LLM/RAG/STT/Realtime, tokens, custos por tenant, tools, Voice/Twilio, CPU, memória e GC.

## Segurança e cardinalidade

- `.env` continua fora do Git;
- métricas não devem conter API keys, Auth Tokens ou senha bootstrap;
- URLs de exporter e credenciais de serviços ficam em configuração de ambiente;
- `tenant_id` como label pode ser desligado com `OBSERVABILITY_TENANT_LABELS=false`;
- IDs únicos por requisição/chamada não são labels Prometheus.

## Banco de dados

A v0.12 não cria nova migration. O head Alembic continua sendo `0007_voice_realtime`.

## Compatibilidade

A v0.12 parte da v0.11.1 já validada. O upgrade executa a suíte completa; o alvo esperado passa de 28 para 34 testes.
