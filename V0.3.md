# v0.3 - Tool / Function Calling

## Objetivo
Transformar a camada de LLM em um agente capaz de solicitar ferramentas sem dar ao modelo acesso direto ao banco ou a APIs.

## Fluxo de segurança
1. O modelo recebe apenas schemas das tools permitidas.
2. O modelo pode retornar `function_call`.
3. O backend valida nome e argumentos.
4. O backend verifica autorização.
5. O backend executa a função.
6. O backend registra `tool_calls`.
7. O resultado volta como `function_call_output`.
8. O modelo produz a resposta final.

## Tools da v0.3
- `check_price` - leitura
- `get_customer_by_email` - leitura e tenant-scoped
- `check_availability` - leitura
- `create_lead` - escrita com idempotência

## Decisões importantes
- `strict=true` em todos os schemas.
- `additionalProperties=false`.
- `parallel_tool_calls=false` nesta etapa.
- VIEWER não pode executar tools de escrita.
- `Idempotency-Key` é usado para proteger side effects.
- `agent_runs` registra total de responses e tool calls.
- `tool_calls` grava hashes e metadados, não argumentos/resultados brutos.
